# Vapor Docs Server

Docs serving and docs publication service for Vapor.

Initial implementation uses Axum/Tokio.

## Responsibility

- serve current docs and static docs assets;
- serve versioned docs;
- accept docs publication from authorized root/deploy tooling;
- expose docs state for export/import.

## Route

Expected public route behind the root reverse proxy:

```text
/docs/
```

## State

Owns uploaded/generated docs artifacts and docs version/current pointer
metadata.

## Routes

```text
GET  /healthz
GET  /v1/status
GET  /
POST /v1/current
POST /v1/current.tar.gz
GET  /v1/releases
POST /v1/releases/<release-id>/promote
GET  /v1/export
```

`GET /v1/status` is public and reports the current docs readiness, state path,
upload limit, and temporary auth model. It must not expose tokens.

`POST /v1/current` accepts a single HTML document for quick smoke tests.
`POST /v1/current.tar.gz` accepts a gzip-compressed tar archive containing a
static docs tree with `index.html` at the archive root.

Both routes are compatibility publication routes. They create or reuse a
content-derived immutable release, promote it, and materialize the existing
`current/` tree so old serving/deployment behavior remains compatible.

`POST /v1/releases/<release-id>/promote` promotes an existing release and can be
used as rollback by promoting an older release.

Archive uploads reject absolute paths, parent-directory traversal, duplicate
normalized paths, symlinks, hardlinks, and other non-file/non-directory entries.
They also enforce separate extracted-byte and file-count limits.

## Release state

```text
state/docs/
  releases/
    <release-id>/
      release.toml
      site/
        index.html
        ...
  current.txt
  current/
```

`current.txt` records the promoted release. `current/` is a materialized
compatibility tree used by the current static file server and by rollback to an
older binary.

Release IDs generated by compatibility routes are content-derived:

```text
legacy-html-<sha256-prefix>
legacy-archive-<sha256-prefix>
```

`GET /v1/export` returns a release catalog/manifest, not full site file bodies.
Whole payload recovery remains covered by the root state bundle until a
service-owned streamed export/import format exists.

Protected routes expect:

```text
Authorization: Bearer <VAPOR_DOCS_ADMIN_TOKEN>
```

## Non-goals

- Steam/GitHub identity authority;
- diagnostics upload storage;
- homepage/legal content ownership;
- deployment orchestration.
